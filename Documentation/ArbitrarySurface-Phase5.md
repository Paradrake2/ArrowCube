# Phase 5: automatic mesh-to-topology conversion

## Try the delivered examples

Open **Arrow Cube > Phase 5 > Open Converted Mesh Lab**, or `Assets/Scenes/SurfaceMeshConversion.unity`, and press Play. Expand **SURFACE LAB / Settings**. The shape button cycles through **RectangularPrism, L, T and AngularPrism**. Select a seed, exit mode, coverage, arrow length, opening limit and blocker amount; measured difficulty search is optional.

These puzzles are generated by the existing Phase 4 dependency-order generator from **baked converted mesh data**. They are not hardcoded arrow layouts, and conversion does not consume the test models' authored topology. The standard orbit, zoom, mouse/touch picking, gates, blocked-contact movement, removal animations, hints, undo, hammer and victory flow are used.

Inputs are under `Assets/Resources/ArrowCubeMeshInputs/`. The four self-contained converted assets are under `Assets/Resources/ArrowCubeSurfaces/`. At the default four subdivisions per parent axis, they contain:

| Model | Parent quads | Logical cells | Convex / concave connections |
|---|---:|---:|---:|
| Unequal rectangular prism | 6 | 96 | 48 / 0 |
| L-shaped solid | 14 | 224 | 84 / 4 |
| T-shaped solid | 18 | 288 | 104 / 8 |
| Rotated non-right-angle prism | 12 | 192 | 60 / 0 |

Counts describe undirected refined boundaries. Coplanar internal connections are counted separately. The L/T include inside corners; the angular prism includes skewed cells and oblique folds. All four have verified generated dependency puzzles. The converted lab uses its own `arrow-cube-imported-surfaces.json` save and sandbox file.

## Convert your own model

1. Open **Arrow Cube > Phase 5 > Mesh Conversion Tool**.
2. Select a readable Mesh asset, or select a scene MeshFilter and click **Use selected MeshFilter**. Enable **Bake filter world transform** if its rotation, scale and position should become part of the converted geometry. The converter recomputes normals from winding; imported shading normals are not connectivity data.
3. Alternatively click **Load explicit-quad OBJ?**. This preserves the original four-vertex faces, including Blender exports, without depending on Unity's triangulation. UV, normal and material references in the OBJ are ignored.
4. Configure **Settings**. Start with `Subdivisions = 4`, `TargetCellSize = 0`, the default tolerances, and `EdgeExits = ConvexOnly`. A positive target cell size replaces the uniform subdivision count.
5. Click **Convert & validate**. The Scene view shows an opaque, colored preview. Review cell outlines/IDs, directions, normals and seam connections using the debug toggles. The selected source object is temporarily hidden in the Scene view while its converted preview is shown, then restored; its MeshRenderer settings are not changed.
6. Review the report and warnings. On failure, gray wire geometry provides context and red markers identify the first reported invalid boundary or the implicated faces when a spatial diagnostic is available. Correct the input/settings and convert again.
7. Click **Save converted surface?**. Prefer `Assets/Resources/ArrowCubeSurfaces/` and put only successfully baked converted assets in that folder. The asset contains the validated topology, exact geometry and conversion settings; runtime gameplay does not need the original mesh. Preserve older assets if saved puzzles must continue using them.
8. Set **Puzzle seed** and click **Play generated puzzle (standard controls)**. Save the current scene if prompted. The tool opens a temporary gameplay scene referencing the saved asset and starts Play mode. The normal surface-lab menu supplies the generation settings; changing those settings does not reconvert the mesh.

Conversion is a snapshot. Reconvert after changing source vertices, transforms, winding, grouping or conversion settings. Change density in the conversion tool and rebake; the converted lab intentionally does not reinterpret baked cell density as an authored-grid setting.

You can also select a Converted Surface asset in the Inspector and click **Inspect converted surface**. Blank/invalid assets show a validation message. **Create Missing Example Assets** recreates missing example inputs, converted assets and the example scene without overwriting existing examples.

### Blender / external model requirements

- Supply **one closed, connected, orientable manifold shell**, with consistent outward face winding. Close holes and remove internal, overlapping, duplicate and disconnected faces. A surface touching itself at a point/edge is not a valid shortcut for joining solids.
- Keep intended cells as **convex planar quads**. Coplanar neighboring quads may form larger regions, but their boundary partition must already match: a long edge opposite two short edges is a source T-junction and requires preprocessing.
- Apply the intended modeling transforms, recalculate outward orientation, and export **OBJ with quads preserved and triangulation disabled** for the most reliable path. The raw OBJ loader accepts `v x y z` and four-vertex `f` records, including slash indices and negative vertex indices. It does not convert triangles or n-gons into quads. Units/axis orientation are retained; rotate the model before export or bake a MeshFilter transform as appropriate.
- If using Unity's normal model importer/FBX, enable **Read/Write** on the source mesh. Its triangles must have a unique complete pairing into convex planar quads, or you must supply a **Mesh Quad Definition** companion containing four source vertex indices per quad in outward boundary order. Companion indices refer to the actual Unity mesh buffer, not necessarily the modeler's pre-export index numbering.
- Duplicate render vertices at UV/normal seams are supported through exact/configurable positional welding. Material submeshes are supported, but automatic triangle pairs must belong to the same submesh. Texture/UV/material appearance is replaced with the puzzle's opaque region palette.
- Avoid tiny slivers, extreme scales and nearly coincident independent surfaces. Default welding is `0.00001` local units and minimum cell size is `0.005`. Welding may not exceed 1% of the configured minimum cell size. Use zero for exact welding; positive tolerance must be at least `1e-9`. A vertex matching multiple weld anchors is rejected, rather than chained/averaged ambiguously.
- Planarity/convexity use the existing `SurfaceQuad` contract: nondegenerate consistently wound corners, with plane tolerance `max(1e-5 local units, quad diagonal * 1e-5)`. The converter does not flatten materially warped quads.
- The default maximum fold is 170 degrees; the author may set 10..175 degrees. Near-antiparallel folds need a bevel/bridge patch. Very sharp folds can produce long offset joins even below the limit; bevel these when necessary for clean arrow presentation.

## Pipeline and responsibilities

All conversion and authoring types live in the Presentation assembly, leaving the logical topology, movement and generator Unity-independent. Components are separated by responsibility:

| Component | Responsibility |
|---|---|
| `MeshConversionSettings`, report and diagnostic types | Limits, policies, immutable-result settings copy, error codes and spatial locations |
| `MeshSourceReader` | Read static Unity buffers, bake transforms and deterministically weld render seams |
| `MeshGeometryValidation` | Degenerate/invalid faces, enclosed-volume orientation and optional uniform inward repair |
| `MeshConnectivity` | Exact shared-edge pairing, consistent winding, closed manifold connectivity and vertex fans |
| `MeshIntersectionValidation` | Bounded broad-phase sweep and conservative triangle contact/intersection checks |
| `MeshQuadExtraction` | Native quads, verified explicit companion groups, or proven unique triangle pairing |
| `MeshSubdivision` | Shared-axis constraints, consistent edge sampling and density limits |
| `MeshSurfaceConverter` | Orchestration, fold classification, builder connections, region colors, identity and final validation |
| `ConvertedSurfaceAsset` | Versioned exact-bit baked packet, integrity validation, caching and save-geometry registry |
| `QuadObjReader` | Explicit-quad OBJ interchange path |
| Editor window / debug drawing / demo menu | Practical conversion, inspection, saving, example creation and launch workflow |

`MeshSurfaceConverter.Convert(mesh, settings)` returns `ConvertedMeshSurface`, containing a `SurfaceShapeDefinition`, `QuadSurfaceGeometry`, content digest and report. The overload accepting a `Matrix4x4` bakes a finite, numerically invertible transform (absolute determinant at least 1e-10) before analysis. The mesh-reading entry point belongs on Unity's main thread. Its immutable logical result can then be passed to the existing native worker or cooperative WebGL generator.

### Reading, welding and geometric validation

The reader accepts exclusively triangle submeshes or exclusively quad submeshes. It snapshots positions/indices; imported vertex normals do not define logical headings. Vertices are sorted lexicographically by position. Exact duplicates, or vertices within the configured tolerance, share a deterministic anchor. Anchors are not averaged or transitively merged. Ambiguous multiple-anchor matches fail explicitly; nonzero seam snapping is reported.

Faces must be nondegenerate. Shared endpoint pairs must have exactly two incident faces with opposite edge orientation. Face adjacency must form one connected shell; incident face fans must also be connected at every vertex. Holes, T-junctions, duplicate faces, pinches and non-manifold edges are rejected.

A bounded spatial sweep checks source triangles for intersections away from legal manifold boundaries. Quads are triangulated only for this geometric test, not for logical movement. Numerical contact tolerances are conservative; clean geometry is required for features at the floating-point/tolerance scale. Validation does not claim unrestricted exact-arithmetic CAD certification.

The signed enclosed volume establishes outward orientation after consistent winding has been checked. A uniformly inward shell can be reversed only if the author explicitly enables repair. Mixed winding is rejected before this step; the tool never guesses a local orientation repair.

### Deliberate quad extraction

**Native quads / quad OBJ:** retain each four-corner polygon after validation.

**Explicit companion:** each ordered quad must cover exactly two source triangles, agree with their winding and boundary order, and collectively cover the source exactly once. A stale companion referencing another mesh or invalid indices fails. Companion triangle pairs currently also require the same submesh; use native quads/quad OBJ or unify that pair's submesh if necessary.

**Automatic triangle pairing:** shared-edge pairs become candidates only when they form a nondegenerate convex planar quad with consistent normals and submesh membership. The converter builds a candidate graph and proves that every component has **exactly one perfect matching**. It does not greedily select the first adjacent pair. Zero solutions, multiple solutions, components above 512 triangles or an exhausted search budget require explicit grouping/preprocessing. The default search budget is 100,000 states.

For example, a simple triangulated rectangular prism is unambiguous. A triangulated hexagonal cap can have multiple valid quad groupings and is deliberately rejected; an explicit companion resolves it. Complex general triangle meshes require external quad remeshing, which this phase does not attempt.

### Deterministic subdivision

Each parent quad has a U and V interval count. Uniform subdivisions initialize both equally. With target cell size, counts are the ceiling of the larger opposing edge length divided by that target. Per-patch row/column overrides are supported.

Shared boundaries constrain the corresponding patch axes to have equal interval counts, including when a local U edge connects to another patch's V edge. A union of these constraints propagates the maximum requested count through each component. If propagation is disabled, inconsistent requests fail with `SubdivisionMismatch`.

Grid points along shared edges use one canonical endpoint order, interval index and count. Both neighboring patches reuse the same vertex ID and exact sampled position. Interior points use bilinear interpolation. A final shared-boundary pass constructs adjacency from those actual vertex IDs, so there are no one-to-many cell boundaries or approximate center-distance guesses.

The tool does not reduce density to fit limits. It rejects more than 64 intervals on a patch axis, more than the configured total cells (default 16,384; absolute maximum 65,536), or cells narrower than the configured minimum. Source input is bounded to 200,000 vertices and 20,000 coarse faces. The intersection validator also has a fixed two-million candidate-check budget. These limits produce diagnostics instead of unbounded search.

Patch overrides use **canonical parent patch IDs**. To inspect them, temporarily convert with one subdivision, target size zero and no overrides; each displayed cell ID is then its parent patch ID. Restore the desired density and add overrides. IDs remain stable for unchanged effective source geometry; changing/baking transforms or remodeling can change canonical ordering.

### Adjacency and heading transport

Every quad uses the established BL, BR, TR, TL winding. Its oriented edges correspond to Down, Right, Up and Left. If a boundary in direction `dA` meets the reverse-oriented boundary `dB` of another cell, the destination heading is `Opposite(dB)`:

```text
A --dA--> B, heading Opposite(dB)
B --dB--> A, heading Opposite(dA)
```

`SurfaceTopologyBuilder.Connect` records both halves and validates the inverse mapping. This works at flat, convex, concave and arbitrary supported dihedral angles. The movement simulator receives only IDs, headings and metadata, as before.

### Fold sign and edge exits

For outward normals `nA`, `nB` and the shared edge tangent `e` following A's outward winding:

```text
angle = atan2(length(cross(nA, nB)), dot(nA, nB))
sign  = dot(e, cross(nA, nB))
```

Within the configurable coplanar angle (default 0.05 degrees, supported 0.001..0.5), the connection is flat. Otherwise positive sign means convex and negative means concave. Indeterminate signs and folds exceeding the maximum are rejected. `atan2` avoids the poor precision of `acos` near coplanarity.

| Kind | `IsGeometricEdge` | `AllowsEdgeExit`, default |
|---|---|---|
| Coplanar | false | false |
| Convex | true | true |
| Concave | true | false |

`EdgeExits = Disabled` is a conservative author override that disables ordinary exits while retaining physical folds. It does not authorize concave exits. Directional gates remain separate, puzzle-owned data. The level's exit rule must also permit ordinary exits, and ordinary exits retain priority over gates. No angle/convexity logic was added to movement.

### Geometry, rendering and gameplay

Output cells retain real corners, derived normals, local directions, seam positions and physical dimensions. `QuadSurfaceGeometry` revalidates every shared boundary and its fold metadata. The existing Phase 3 rail, stroke, arrowhead, surface occlusion and animation code consumes this geometry directly; no imported-shape-specific renderer or simulator exists.

The surface mesh now batches equal palette materials. Default converted examples use three surface material groups, rather than one draw group/material per cell. Per-face normals, opaque materials and depth testing are retained. Historical cubes still have their six distinct face materials/submeshes. Arrow rendering remains the standard per-arrow system.

`SurfaceGenerationDemo` accepts referenced converted assets and reuses its existing seed/settings UI and `GameplayController.StartSandboxGeneration`. A too-coarse surface reports conflicting arrow settings, keeps the previous puzzle and does not silently shorten paths or weaken difficulty requirements. As in Phase 4, measured scores and blocker averages are declared soft search goals; hard opening limits, profile floors, valid solo routes and complete solvability remain acceptance requirements.

## Identity, persistence and compatibility

Conversion version is **1**. Welded source positions and consistently wound quads receive canonical ordering; cell ordering and tie-breaking are deterministic. Reordering source vertices/faces or rotating the starting corner of a quad preserves the result.

A SHA-256 content digest includes the conversion version, effective conversion settings, final corners/colors and every logical boundary/heading/fold/exit flag. The stable ID is `arrowcube/mesh/<digest>`. Geometry or relevant settings changes therefore cannot be mistaken for another shape with the same cell count. Equivalent effective quad geometry can share identity across native, explicit-companion and uniquely paired triangle inputs. Names and material appearance do not define identity.

`ConvertedSurfaceAsset` stores an explicitly versioned binary packet with exact float bits, settings and immutable topology snapshot. Loading verifies the content digest, shape identity and geometry/topology agreement. Cached data is reused during gameplay. Source mesh analysis is absent from arrow traversal and removal.

Generation still uses Phase 4 **version 6**, and existing shape recipe format **2** already carries the new shape identity/snapshot. No historical recipe encoding or generation version was changed. Cube recipes 1?5, default cube version 5, authored non-cube assets, fingerprints and save schemas remain compatible.

Saved puzzles retain `SurfaceAssetId`/version. The geometry resolver recognizes converted IDs, locates a registered or Resources-bundled asset, checks its topology digest and binds its corners to the restored IDs. The logical recipe can regenerate without the original mesh, but rendering still requires the correct converted geometry asset. Replacing an asset with changed geometry creates a different content ID; keep the old asset if old saves must render.

Trajectory caches remain scoped to immutable topology/path/map identities and rules. Conversion does not weaken their separation between shapes.

## Validation and representative performance

Final counts and artifacts are recorded in `TestResults/MeshConversion/Summary.md`.

EditMode covers all four native fixtures, unique automatic pairing, explicit grouping, ambiguity rejection, reversed winding, invalid/degenerate faces, disconnected/non-manifold shells, actual self-intersection, unmatched boundaries, seam welding and ambiguous anchors, target-size/override subdivision, minimum dimensions and limits, transformed geometry, reordered inputs, baked asset and generated-recipe round-trips, OBJ input, cancellation and multiple densities. All connections are checked for reversible headings and matching boundary positions. Generated puzzles verify occupancy, solo exit rules, dependencies, opening limits, deterministic fingerprints and complete removal replay.

PlayMode loads the delivered converted scene and uses real Input System mouse and touch events to remove every arrow on all four models. It exercises blocking without occupancy changes, fold-crossing animation, victory, undo, save restoration, selector controls, measured difficulty and too-coarse recipe errors. Mobile URP captures cover front, rear and animated views, checking finite mesh vertices and visible depth-tested arrow pixels.

Historical cube generation comparison uses all **1,008** puzzles and all deterministic CSV fields, excluding elapsed time. The full existing topology/movement/generation/rendering/save/gameplay suites are included in regression runs.

Representative initial measurements on this machine, gate-only seed 12345, without measured search or independent tuning:

| Model | Cells at n=2 / conversion ms | n=4 / conversion ms | n=8 / conversion ms | Generation ms at n=8 |
|---|---:|---:|---:|---:|
| Rectangular prism | 24 / 0.57 | 96 / 1.43 | 384 / 7.79 | 31.95 |
| L | 56 / 1.52 | 224 / 3.37 | 896 / 15.43 | 108.17 |
| T | 72 / 1.91 | 288 / 6.95 | 1,152 / 20.30 | 183.04 |
| Angular prism | 48 / 1.11 | 192 / 3.07 | 768 / 12.70 | 83.21 |

Reports also record candidate attempts/rejections, net managed-memory change and render-request submission time. Memory change is a `GC.GetTotalMemory(false)` observation, not peak memory/allocation; it can be negative after collection. Render submission includes CPU/driver/shader warm-up and is not a GPU frame-time or sustained-FPS claim. Optional tuning/search, restarts and shader warm-up can add time. Logs/CSV provide the exact measured samples.

## Known limits and next improvements

This supports static, embedded, closed quad-compatible shells. It deliberately rejects open/non-manifold/disconnected/degenerate/intersecting input, ambiguous triangle pairings, severe folds, incompatible source edge partitions and unsatisfiable subdivision limits. It does not perform arbitrary quadrangulation, repair mixed winding, merge one-to-many boundaries, retopologize curves, preserve textures, support skinning/deformation or modify connectivity during play.

Large curved or highly tessellated inputs should be remeshed into sensible planar quad patches first. Limits are bounded failure policies, not a guarantee that every input up to the maximum is fast. The default 16,384-cell cap is conservative; performance measurements here extend to 1,152 cells, not every possible 65,536-cell level. Existing large-puzzle generation and save limits still apply.

Future extraction/remeshing strategies can replace `MeshQuadExtraction` while returning the same validated parent quad data. Useful next work includes richer imported material/color policies, a visual companion-group editor, more complete geometry diagnostics, explicit multi-component/open-surface rules if gameplay expands, and asynchronous/progress-aware conversion for larger authoring inputs. Such work should preserve canonical IDs/versioning, full-edge manifold adjacency and the shared generator/movement contracts.
